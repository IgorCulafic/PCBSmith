## Audit rules

Status meanings:

- **PROVEN** — the root agent inspected the implementation and retained
  authority, ran the proportional regression/static gates independently, and
  found no unmet firing fixture.
- **PROVISIONAL** — implementation exists and focused evidence is green, but a
  required architecture, integration, serialization, or full-regression gate
  is still outstanding.
- **IN PROGRESS** — a bounded implementation slice is actively being changed.
- **UNPROVEN** — the required evidence is absent, stale, indirect, or has not
  yet received root review.
- **NOT STARTED** — the authoritative design requires the capability and no
  implementation claim is being made.

For every accepted slice the evidence bundle must include:

1. versioned and canonical input/result IR where the slice crosses a subsystem
   boundary;
2. retained inputs sufficient to revalidate every derived success, failure,
   metric, authority, applicability, and fingerprint after serialization;
3. exact or conservatively bounded geometry and arithmetic, with unsupported
   data unable to serialize as a numeric pass;
4. deterministic work budgets, input-order reversal, repeated-run, one-less,
   rollback, and tamper fixtures where applicable;
5. proof that legacy/default behavior is unchanged unless migration is an
   explicit firing fixture;
6. focused tests, adjacent regression tests, Ruff, strict mypy, and the
   applicable serialized KiCad/read-back/DRC gate; and
7. root inspection of what the tests actually prove. A green test count alone
   is not completion evidence.

## Root-written execution contracts now active

### R4.5A — metrics authority envelope

The executor may implement but may not redefine these decisions:

- The result retains the immutable bus bundle, capacity certificate, geometry
  registry, member prefixes, validation context, and policies needed for an
  after-validator to replay every metric and rule.
- A hard pass/fail may use exact rational/integer evidence or a conservative
  interval whose direction proves the result. A floating approximation to an
  algebraic diagonal length is not exact authority.
- Adjacent pitch/edge clearance is exact only when the certified centerlines
  and translation prove physical minimum separation; constant tangential
  translation is insufficient.
- Boundary order uses explicit boundary/portal/section identities, never
  positional `zip` truncation.
- Pairwise parallel/coherence denominators are named as such and are not
  mislabeled as certificate span. Empty denominators are not applicable.
- Hard electrical enforcement requires complete evidence, applicability,
  validation, and any required stackup/reference/propagation model. Otherwise
  the terminal state is hard-constraint-unverified.

### R5.6a — rectangular compatibility adapter

- The adapter is opt-in and compatibility-only; it cannot become the default
  placement or routing path.
- Its source layout, netlist, profile, policy, and rectangular-envelope
  assumptions are retained and fingerprinted.
- It preserves every `BoardLayout` field and fixed/non-target copper. Only the
  already-declared target transformations and target route replacement may
  differ.
- Geometrically equivalent input must reach the same exact accepted board;
  routed-unchecked is not equivalence.
- Existing `placement_search`, `route_board`, and default generator behavior
  and deterministic outputs remain unchanged.

### R6.1b-a — fabrication geometry for a declared sensor-isolation candidate

- Numeric slot/web/tab limits require units, qualified source/evidence,
  applicability, selected fabrication/assembly profile IDs, and active
  qualification. Generic examples/advice cannot supply a hard number.
- Slots/cutouts are exact declared negative geometry. Webs/tabs are exact
  positive laminate regions, never inferred as whatever remains.
- Selected constraints compare exact feature witnesses at equality and one
  representable unit below, retaining the exact constraint/source IDs.
- The serialized result retains enough declarations, profiles, live geometry,
  and context to recompute each disposition and fingerprint.
- This slice makes no copper-crossing, bridge-budget, thermal-performance, or
  humidity-validation claim; those are separate later slices.
