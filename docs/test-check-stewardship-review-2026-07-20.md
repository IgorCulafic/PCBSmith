# Test and production-check stewardship review — 2026-07-20

## Executive assessment

The suite is large, but “about 2,500 checks” is not the right model. The current
collection has **2,597 pytest cases generated from 1,885 authored test
functions in 207 files**. Parametrization and tamper/boundary matrices expand
one authored contract into several cases. The repository has far fewer
production check entrypoints: a name-based static inventory found 71 candidate
check/validation functions, of which 40 are public. This candidate count is not
complete because model validators and inline invariants are also authorities.

The conclusion is neither “the count is fine” nor “delete most of it.” The
suite contains valuable exact-authority regression evidence, but it is heavily
unit-weighted and has some coupling and policy debt that should be addressed by
contract, applicability, and runtime—not by age or raw count.

## Production authority layers

The name-based inventory groups the obvious functions as follows:

- 19 `design_checks` functions: topology-aware geometric/craft review;
- 10 `virtual_drc` functions: early in-memory copper, edge, courtyard,
  connectivity, and silkscreen screening;
- 2 KiCad CLI adapters: final ERC and DRC tool authority;
- 2 functions classified as semantic evaluators;
- 38 domain/contract validators and specialized evaluators.

These layers are not automatically duplicates. Virtual DRC is useful before a
board exists and KiCad DRC remains final file authority. Specialized semantic
evaluators cover intent that neither clearance DRC can infer. The stewardship
problem is to document applicability and precedence so that a heuristic cannot
silently become a universal blocker.

## Findings and actions

### Corrected now

1. **Global acute-corner blocker contradicted its rulebook.** Rule 11.1 was
   documented as on policy hold because right-angle/acute-corner craft rules
   are not universal SI or fabrication defects. Nevertheless,
   `run_design_checks()` always ran it as a blocker. It is now off by default
   and requires an explicit `off|advisory|blocker` policy selection. Its tests
   remain and exercise the declared blocker behavior.
2. **Quick pytest environment differed from standard/deep.** The quick
   verification gate now also disables ambient pytest plugin autoloading.

### Keep, but improve

1. **Parameterized tamper and boundary matrices.** These produce much of the
   case expansion and are appropriate for fail-closed authority objects. Keep
   them unless mutation/coverage evidence shows a row is redundant.
2. **Literal semantic fingerprints.** Keep when they prove deterministic bytes,
   replay binding, or stale-authority rejection. Avoid pinning values that only
   mirror incidental implementation order.
3. **Focused internal geometry tests.** Testing private kernels is reasonable
   while they are the only exact geometry seam, but 43 files doing so signals a
   boundary-design cost. Publish a supported physical-geometry test/API layer
   and migrate consumers gradually rather than mass-rewriting tests.
4. **Unit-heavy authority coverage.** Preserve it, but add a small number of
   high-value persisted-project and live-KiCad proofs. More unit cases cannot
   prove that normal project generators invoke the authorities in the correct
   order.

### Review later with measured evidence

1. Capture per-file and slowest-test duration data from a warnings-as-errors
   full run. Source length is not a runtime proxy.
2. Map every production finding ID to rule source, applicability predicate,
   severity policy, caller stage, and final authority. This will expose true
   overlaps and orphan checks.
3. Review numeric-coordinate assertions by category: exact input/output
   geometry, derived invariant, regression artifact, or incidental layout pin.
   Replace only the last category with semantic invariants.
4. Consolidate duplicated fixture construction where it improves maintenance;
   do not combine distinct failure reasons merely to reduce the count.
5. Investigate the earlier one-off Hypothesis slow-generation incident under a
   timed full-suite run. Do not suppress the health check without a cause.

## Decision

No bulk test deletion is justified. The highest-value changes are applicability
scoping, production-call-path tests, runtime visibility, and reducing private
kernel coupling. The first harmful applicability mismatch was fixed in this
review. The remaining candidates should be handled incrementally after the
next full timed gate and production-check mapping, not while the Retro-Pad
mechanical brief is awaiting a user decision.

## Phase 16 closure addendum — 2026-07-23

Phase 16 implemented the deferred ownership and runtime work without bulk test
deletion. `tools/audit_test_and_check_suite.py` now emits schema v2 and:

- accepts retained pytest JUnit XML for measured per-test/per-file runtime;
- separates coordinate/scale numeric pins from work/time/memory budget pins;
- assigns production check candidates to a shared canonical authority or an
  explicit module-local owner;
- reports lexical caller coverage as triage evidence;
- distinguishes framework validators from module-level public entrypoints.

The post-implementation inventory contains 2,763 collected cases from 2,033
authored functions in 229 files. It finds 88 name-matched check/validation
candidates, 52 module-level public candidate entrypoints, 112 coordinate/scale
numeric assertions, and 141 budget numeric assertions. No module-level public
candidate is lexically unobserved. Dynamic dispatch, same-file calls, Pydantic
validators, and inline invariants remain documented limits of the static
method.

The highest-count coordinate/scale files were manually sampled. Their values
protect exact KiCad transforms, mask/aperture geometry, GLB alignment, physical
render scale, placement moves, or accepted bounded-pilot identities. No pin was
removed solely because it is old or absolute. Board-specific pins remain
bounded to their board/adapter rather than promoted into shared authority.

The 2026-07-20 Hypothesis event is closed as a transient host
scheduling/preemption stall during a timed integer draw. The strategy produced
100 valid examples in 0.09 seconds with typical draw time below 1 ms and no
filtering; 50 isolated pytest processes passed. The health check remains
enabled and future full runs retain JUnit timing. Full rationale and evidence
are in `docs/phase16-workflow-authority-contract-2026-07-23.md`.
