# PCBSmith Phase 4A Board Handoff Design

## Goal

Phase 4A turns the current KiCad-native schematic proof into the first KiCad-native board proof. A user request for a complete current-limited LED circuit should produce a review bundle containing both a readable schematic SVG and a meaningful board SVG.

## Scope

This phase stays deliberately narrow:

- Support the existing LED demo circuit path.
- Export a KiCad `.kicad_pcb` with visible footprints, board outline, nets, and simple front-copper traces.
- Use embedded generic footprints generated by PCBSmith so the demo does not depend on local KiCad footprint library installation.
- Add simple VCC and GND board terminal pads so the preview has real power connection points and KiCad DRC does not report dangling power traces.
- Keep KiCad as the source of truth for rendering and validation.

This phase does not add autorouting, a custom PCB editor, a real LLM provider, image-to-board workflows, or broad component coverage.

## Architecture

`kicad_export` will continue to own KiCad handoff generation. It already maps PCBSmith schematic symbols into native schematic symbols. Phase 4A adds a matching board rendering path:

- derive supported board parts from native schematic symbols;
- assign each part a small embedded footprint model;
- derive net names from the supported schematic wires and labels;
- render footprints, pads, tracks, and the board outline into the skeleton `.kicad_pcb`;
- let `kicad_review_bundle` and `kicad_preview` export both schematic and board SVGs.

The generated board is a deterministic review artifact, not a final layout. It proves that PCBSmith can create KiCad-readable board data and gives the user something visual to judge.

## Data Flow

1. The AI demo plan creates VCC, resistor, LED, GND, wires, and net labels.
2. The approval loop applies the plan to PCBSmith JSON.
3. The KiCad exporter renders the schematic as it does today.
4. The same exporter derives board nets from the native schematic connectivity.
5. The board renderer emits:
   - a compact Edge.Cuts rectangle;
   - one generic two-pad footprint for each non-power component;
   - one generic one-pad terminal footprint for each power endpoint;
   - net declarations;
   - simple F.Cu traces connecting the demo chain.
6. KiCad CLI validates and exports SVG previews.

## Testing

Tests should assert the LED fixture board export includes:

- KiCad PCB header and compact outline;
- embedded resistor and LED footprints;
- pads assigned to the expected net names;
- visible F.Cu traces for the LED chain;
- existing schematic behavior remains unchanged.

The full development check should continue to pass.
