Unsupported differences, changed pad geometry, values against an old netlist, changed outline and stale source hashes fail before output. Already matching layouts retain their exact existing fingerprint. No CAD is generated or modified by the command.

2. **Confirmed: acceptance inputs required repeated manual copying.** `routing_preparation.py` now accepts typed, SHA-bound file references (optionally an explicit JSON pointer into an existing record). It obtains board, current transaction, visual review and component execution directly from the hash-checked current generation, checks exact layout/netlist semantics, and replays the existing routing-entry gate. It neither creates decisions nor changes failing engineering fields. Output is `ready_inputs` or `blocked_inputs`, never routing acceptance. Failed source/geometry validation creates no successful preparation output.

3. **Confirmed: repeated model CLI arguments drifted from the selected policy.** `production_readiness.prepare_selected_board_models` and its `models` CLI derive saved-board preflight directly from the retained, source-validated selection, including rationale, requirements, hashes and transforms. The publication consumer calls the same owner. Historical bundles remain readable under their original scope, but new preparation refuses missing policy. This credits the earlier 2B policy checks and engineering-preview prevalidation rather than replacing them.

4. **Confirmed: a checked substitution had no supported revised-publication provenance.** `routing_revision.py` derives a distinct unchanged-copper proof from the actual accepted predecessor transaction and replayed qualified same-footprint substitution. The original routing receipt remains bound to the original board. Retained generation artifacts, revision/request/check files, exact current native inputs, raw ERC/DRC sections, copper/pad/net/placement hash and working revision are checked. Ordinary live publication can consume this separate proof through the existing registered boundary.

5. **Confirmed during implementation review: unchanged copper alone is insufficient.** Revised publication additionally requires `RevisionPublicationAuthority`: a fresh replay-derived engineering gate, exact netlist/component review, canonical layout and rule profile. Saved geometry must match the current layout/netlist; required IC obligations must be complete; selected readiness MPNs and the updated specification must match. Every checked substitution input must be retained in publication support. Old readiness, missing fresh authorities, changed support files and different boards remain blocked. Fresh native DRC, readiness and visual checks still run through existing publication owners. Source interpretations remain human/engineering review obligations, not facts proven by hashes.
