## 2. Recurring handover requirements and actual copper

`require_recurring_deliverables` is enforced at new predesign approval, registered generation and publication: PCB, schematic, project, interactive BOM, editable floorplan and preview. Generated review worklists contain those six roles. Existing schemas remain readable; omitting roles cannot select historical policy at a new publication entry point. Requested additional files remain mandatory under the reviewed inventory.

Handover validates an iBOM producer receipt against the exact current native inputs and HTML bytes; vector/preview hashes must match the retained reviewed floorplan. Merely adding matching filenames or caller hashes is insufficient. Human display and observations remain actual reviewer responsibilities; no decision is filled automatically.

Requested isolation is now checked at handover against native straight-track and simple front-SMD copper geometry. Each circular pad/track boundary is enclosed with a circumscribed polygon: radius is enlarged by `1/cos(pi/256)` for 64 segments per quadrant. This gives a conservative lower bound on circuit-to-floating-copper spacing, independent of KiCad SVG tessellation. The existing 0.02 mm circuit-shape comparison tolerance never relaxes the reviewed clearance. Joined background/circuit copper and missing circuit copper are rejected; edge clearance applies to all retained copper. Required minima come from the reviewed board rules, not caller-supplied acceptance flags.

Supported check scope: one rectangular outline, straight front tracks, front SMD rectangular/roundrect/circular/oval pads with native rotations. Vias, arcs, zones and other copper graphics fail closed pending a suitable geometry authority. The exporter can still produce inspection artwork for its broader historical subset; such artwork is not handover acceptance. This deliberately does not claim generalized zone CAM or physical laser qualification, and does not reopen historical accepted jobs.

## 3. Avoiding demonstrated unnecessary work

Final `visual-review` CLI calls require `--native-checks DIR` with current successful all-severity ERC/DRC/parity receipts before invoking the renderer. Changed board, schematic, project, rule/library table or report bindings block cheaply. This reuses existing exact receipts; it does not automatically rerun native tools, change rules or invent inspections. Registered production publication retains its combined native rule/omission review before final rendering. Placement review remains separate because it precedes complete routing. Arbitrary internal/research renderer calls are not production acceptance.

Diagnostic collection now runs after current 3D source images exist. The new `visual-complete-diagnostics` command requires a live shared worker, unchanged declarations, current board/model identities and all generated artifact hashes. It copies only missing diagnostics from inventoried current images into an immutable successor, grants no inspection decision and never renders. Stale inputs or a changed declaration are rejected. The original 255.766-second rendering operation was retained and not repeated; no broad benchmark speedup is inferred.

`outputs/consolidated-workflow-2026-09-22/actual-reuse-evidence.json` binds the real completion, current native precheck, final recovery timers and strengthened handover. Data preparation and inspection still require work; this does not claim a completely automatic one-command board workflow or eliminate all clerical overhead.
