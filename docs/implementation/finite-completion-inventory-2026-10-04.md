# Explicit finite completion inventory — October 4

The user instructed “then why stop, just finish them” after the retained PowerTrace and PowerSwitch diagnostics. The shared job controller previously could not express a one-object placement recovery after an annotation correction, or a fourth native-preparation invocation after two pre-output input failures. This separately scoped platform change adds an explicit, hashed completion inventory to `continue-authorized`.

Each declared build stage permits one invocation; placement/final rendering and inspection may each have two. Undeclared operations are blocked. The inventory cannot renew itself, cannot regenerate an existing placement, and cannot override the two-invocation automatic routing limit or its meaningful placement/connectivity-change requirement. Failure still requests diagnosis. Existing source, native, review, routing and handover gates remain required. Clocks, correction cycles, all attempts and the exact predecessor are retained; this is not a pass under the original timing allowance.
